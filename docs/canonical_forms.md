# 正準形の宣言（コード→ASTパーサ向け）

実装計画 §2.6 に対応する。**パーサ本体は実装しない。**将来書くときのために、
リテラルに具体化すると別のopと同じになる組と、その正準形を先に決めておく。

## 最初に：往復はASTの同一性としては閉じない

**将来パーサを実装する際の受け入れ条件は、ASTの同一性ではなく意味的等価性とする。**

`x * 2` をパースすると `double` になる。それが元々 `mul_k` をリテラル2に具体化したもので
あっても、`mul_k` には戻らない。コードには「どちらのopから生成されたか」の情報が残らないため、
原理的に戻せない。

```python
# 将来の受け入れテスト（AST の一致は要求しない）
assert run(parse(emit(ast)), xs, k) == run(ast, xs, k)
```

ASTの一致を条件にすると、パーサが通らないか、あるいは通すために
コードへ出所の痕跡を埋め込むことになる。どちらも避ける。

## リテラル具体化による衝突と正準形

改訂版 L273-277 が挙げる組。**正準形は専用のopの側**とする。より短く、`k` に依存せず、
日本語表現も自然になるため。

| 具体化した形 | 同じになるop | 正準形 | 出典 |
| --- | --- | --- | --- |
| `ge` @ 1 | `positive` | **`positive`** | L275（要素が整数なので `x >= 1` と `x > 0` は同値） |
| `multiple_of` @ 1 | （恒真） | **フィルタを置かない** | L274 |
| `multiple_of` @ 2 | `even` | **`even`** | L275 |
| `mul_k` @ 1 | （恒等） | **変換を置かない** | L273 |
| `mul_k` @ 2 | `double` | **`double`** | L275 |
| `mul_k` @ 3 | `triple` | **`triple`** | L275 |

これらのリテラルは値域から除外済みなので（`OpSpec.literal_domain`）、
**生成側では衝突が起きない。**この表は生成のための規則ではなく、
外から来たコードをパースするときの規則である。

`OpSpec.shadows` が機械可読な形で同じ対応を持つ。

```python
OP_REGISTRY["ge"].shadows          # ("positive",)
OP_REGISTRY["multiple_of"].shadows # ("even",)
OP_REGISTRY["mul_k"].shadows       # ("double", "triple")
```

## 除外していない紛らわしい組

| 組 | 除外しない理由 |
| --- | --- |
| `lt` @ 1 と `negative` | `x < 1` はゼロを含み、`x < 0` は含まない。**別の関数**（L277） |
| `gt` @ 0、`lt` @ 0、`add_k` @ 0 など | そもそも値域 1〜10 の外なので規定を要しない（L277） |

## パース衝突ではないが振る舞いが同じもの

**この表の対象外。**`behavior_hash`（実装計画 §2.5）が拾う領域である。

| 組 | 性質 |
| --- | --- |
| `desc` と `[asc, reverse]` | 生成コードが違うのでパースでは区別できる。振る舞いは同一 |
| `[square, abs]` と `[square]` | 二乗は常に非負なので `abs` が恒等（L534） |
| `[even, positive]` と `[positive, even]` | 可換（L529） |
| `[even, desc]` と `[desc, even]` | 可換（L530） |
| `[double, triple]` と `[triple, double]` | どちらも ×6（L531） |
| `[add_k, sub_k]` と `[sub_k, add_k]` | どちらも恒等（実測で `is_identity` として検出） |

単一opの言い換えではなく**操作列レベルの縮退**なので、`shadows` には入れない。
パーサが区別できるかどうかとは別の問題であり、扱うのは分割後の漏洩検査（L524 の第5項）。

## 実装するときの注意

- **参照インタプリタを唯一の権威として保つ**（実装計画 §2.7）。パーサが「意味の第2の定義」に
  なってはいけない。受け入れ条件を意味的等価性にするのはそのため
- 正準形を選ぶ規則をパーサに書く前に、この表を更新すること。表とコードが食い違うと、
  どちらが正しいか判断できなくなる
